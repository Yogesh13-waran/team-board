TeamBoard is an enterprise-grade B2B API platform powering AI Knowledge Base integration for customer helpdesks, developer portals, and chatbots. 

The backend is built with **Django 6.1**, **Django REST Framework (DRF)**, **SimpleJWT**, and containerized **PostgreSQL 16**, following clean architecture, strict tenant isolation, cryptographic API key issuance, atomic search usage metering, and role-based access control (RBAC).

## Architectural Highlights

1. **Decoupled Registration via Post-Save Signals**:
   - Company accounts and API keys are automatically generated by a decoupled `post_save` signal on Django's `User` model (`api/signals.py`), registered safely inside `AppConfig.ready()`.
   - API keys are cryptographically generated using Python's `secrets.token_urlsafe(32)` (256 bits of CSPRNG entropy).
   - Roles strictly default to `CLIENT`. Attempts to self-assign `ADMIN` in registration payloads are rejected.

2. **Global-by-Default Security (Zero Trust)**:
   - Configured globally with `JWTAuthentication` and `IsAuthenticated`.
   - Only `/api/auth/register/` and `/api/auth/login/` explicitly exempt themselves via `authentication_classes = []` and `permission_classes = []`.

3. **Atomic Usage Metering & Billing Integrity**:
   - `/api/kb/query/` executes knowledge base keyword search (`Q` objects across `question` and `answer` using `__icontains`) and persists the `QueryLog` inside a single `transaction.atomic()` block.
   - Queries with zero results are still persisted with `results_count = 0` to ensure accurate usage-based billing.

4. **Custom Role-Based Access Control (RBAC)**:
   - `IsAdminUser` permission class in `api/permissions.py` verifies `request.user.company.role == Company.Role.ADMIN`.
   - Non-admin client tokens receive `403 Forbidden`.

5. **Advanced Database Aggregations**:
   - Usage summary endpoint computes platform metrics directly in the database engine using Django ORM's `aggregate(Count('id'))` (scalar reduction), `values('company').distinct().count()`, and `values('search_term').annotate(count=Count('id')).order_by('-count')[:5]` (SQL `GROUP BY`).

## Quick Start Guide

### 1. Environment Configuration

Copy `.env.example` to `.env` (already created with defaults):

```bash
# Verify or edit .env
DB_NAME=teamboard_db
DB_USER=teamboard_user
DB_PASSWORD=teamboard_secure_pass_2026
DB_HOST=127.0.0.1
DB_PORT=5432
SECRET_KEY=django-insecure-teamboard-b2b-api-key-knowledgebase-top-secret-2026
DEBUG=True
ALLOWED_HOSTS=localhost,127.0.0.1,0.0.0.0
```

### 2. Start PostgreSQL via Docker

Launch PostgreSQL 16 Alpine in the background using Docker Compose:

```bash
docker compose up -d db
```

Verify that the database container is healthy:

```bash
docker ps
# Expected output: teamboard_postgres container running and healthy on port 5432
```

### 3. Install Python Dependencies

Install the pinned production dependencies:

```bash
pip install -r requirements.txt
```

### 4. Apply Database Migrations

Apply Django core and custom model migrations to PostgreSQL:

```bash
python manage.py migrate
```

### 5. Seed Knowledge Base & Admin Account

Run the custom management command to seed 15+ curated technical Q&A entries and configure a platform admin account:

```bash
python manage.py seed_kb --with-admin
```

Output:
```text
Seeding TeamBoard Knowledge Base entries...
Successfully seeded KB entries: 15 created, 0 updated. Total in DB: 15.
Platform Admin ensured: username='teamboard_admin', role='admin', api_key='...'
```

### 6. Run the Development Server

Start the Django development server on port 8000:

```bash
python manage.py runserver 127.0.0.1:8000
```

The API is now live at `http://127.0.0.1:8000/api/`.

### 7. Execute Automated Test Suite

Run the full automated test suite covering all 11 required scenarios:

```bash
python manage.py test tests
```

Output:
```text
Creating test database for alias 'default'...
...............
----------------------------------------------------------------------
Ran 15 tests in 11.221s

OK
Destroying test database for alias 'default'...
```

## API Endpoints Specification

### 1. POST `/api/auth/register/`

Public registration endpoint for B2B client companies.

- **URL**: `/api/auth/register/`
- **Method**: `POST`
- **Auth Required**: None (`authentication_classes = []`, `permission_classes = []`)
- **Headers**: `Content-Type: application/json`

#### Request Body
```json
{
  "username": "acmecorp",
  "password": "securepass123",
  "company_name": "Acme Corp",
  "email": "dev@acmecorp.com"
}
```

#### Success Response (201 Created)
```json
{
  "username": "acmecorp",
  "company_name": "Acme Corp",
  "api_key": "vL_2R2728BwhxY2lE0c3o-dJvXbY9mQk0xS8G2fN7oE",
  "access": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJ0b2tlbl90eXBlIjoiYWNjZXNzIiwiZXhwIjoxNzYyMDk3..."
}
```

#### Error Responses
- **400 Bad Request**: If username already exists, or required fields are missing/empty.

### 2. POST `/api/auth/login/`

Public login endpoint. Authenticates credentials and returns a fresh JWT access token.

- **URL**: `/api/auth/login/`
- **Method**: `POST`
- **Auth Required**: None (`authentication_classes = []`, `permission_classes = []`)
- **Headers**: `Content-Type: application/json`

#### Request Body
```json
{
  "username": "acmecorp",
  "password": "securepass123"
}
```

#### Success Response (200 OK)
```json
{
  "access": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJ0b2tlbl90eXBlIjoiYWNjZXNzIiwiZXhwIjoxNzYyMDk3...",
  "company_name": "Acme Corp",
  "api_key": "vL_2R2728BwhxY2lE0c3o-dJvXbY9mQk0xS8G2fN7oE"
}
```

#### Error Responses
- **401 Unauthorized**: Invalid username or password (`{"detail": "Invalid credentials. Please verify your username and password."}`).

---

### 3. POST `/api/kb/query/`

Protected knowledge base search endpoint. Searches question and answer text case-insensitively and logs query usage atomically.

- **URL**: `/api/kb/query/`
- **Method**: `POST`
- **Auth Required**: Yes (`Bearer <access_token>`)
- **Headers**:
  - `Authorization: Bearer <access_token>`
  - `Content-Type: application/json`

#### Request Body
```json
{
  "search": "how to use select_related"
}
```

#### Success Response (200 OK - Matches Found)
```json
{
  "search": "how to use select_related",
  "count": 2,
  "results": [
    {
      "id": 1,
      "question": "What is select_related in Django ORM?",
      "answer": "select_related performs a SQL JOIN and fetches related single-object relationships...",
      "category": "database"
    },
    {
      "id": 2,
      "question": "When should I use prefetch_related vs select_related?",
      "answer": "Use select_related when traversing single-valued relationships via SQL JOINs...",
      "category": "database"
    }
  ]
}
```

#### Success Response (200 OK - Zero Matches)
```json
{
  "search": "unmatched_search_term_12345",
  "count": 0,
  "results": []
}
```
*(A QueryLog record with results_count=0 is still recorded for usage billing).*

#### Error Responses
- **400 Bad Request**: Search field missing or contains only whitespace (`{"search": ["Search term cannot be empty or whitespace."]}`).
- **401 Unauthorized**: No token or invalid/expired token.

---

### 4. GET `/api/admin/usage-summary/`

Protected platform admin usage statistics dashboard.

- **URL**: `/api/admin/usage-summary/`
- **Method**: `GET`
- **Auth Required**: Yes (`Bearer <admin_access_token>`)
- **Permission**: `IsAdminUser` (User's company must have `role == 'admin'`)
- **Headers**: `Authorization: Bearer <admin_access_token>`

#### Success Response (200 OK - Admin User)
```json
{
  "total_queries": 284,
  "active_companies": 7,
  "top_search_terms": [
    { "search_term": "select_related", "count": 42 },
    { "search_term": "transaction atomic", "count": 31 },
    { "search_term": "JWT authentication", "count": 28 },
    { "search_term": "Q objects", "count": 19 },
    { "search_term": "signals django", "count": 14 }
  ]
}
```

#### Error Responses
- **403 Forbidden**: If authenticated user's company role is `client` (`{"detail": "Access restricted: Platform Administrator privileges required."}`).
- **401 Unauthorized**: If request is unauthenticated.

## Postman Collection & Verification

The repository includes a ready-to-run Postman collection located at:
[`postman/TeamBoard_API.postman_collection.json`](file:///c:/Users/yoges/python-teamboard/postman/TeamBoard_API.postman_collection.json)

### Tested Scenarios Covered

| Scenario # | Method | Endpoint | Expected Status | Description |
| :---: | :---: | :--- | :---: | :--- |
| **1** | `POST` | `/api/auth/register/` | `201 Created` | Registration success; captures `client_token` & `api_key` |
| **2** | `POST` | `/api/auth/register/` | `400 Bad Request` | Duplicate username rejection |
| **3** | `POST` | `/api/auth/register/` | `400 Bad Request` | Missing required payload fields |
| **4** | `POST` | `/api/auth/login/` | `200 OK` | Valid login returning JWT access token & credentials |
| **5** | `POST` | `/api/auth/login/` | `401 Unauthorized` | Invalid password or nonexistent username |
| **6** | `POST` | `/api/kb/query/` | `401 Unauthorized` | Knowledge base query without Bearer token |
| **7** | `POST` | `/api/kb/query/` | `200 OK` | Query with matching results; QueryLog persisted |
| **8** | `POST` | `/api/kb/query/` | `200 OK` | Query with zero results; count: 0, QueryLog persisted |
| **9** | `POST` | `/api/kb/query/` | `400 Bad Request` | Missing or blank search term |
| **10** | `GET` | `/api/admin/usage-summary/` | `403 Forbidden` | Standard client token rejected with 403 |
| **Helper** | `POST` | `/api/auth/login/` | `200 OK` | Login as `teamboard_admin` to obtain `admin_token` |
| **11** | `GET` | `/api/admin/usage-summary/` | `200 OK` | Admin token succeeds with aggregated metrics |

### How to Run in Postman
1. Open Postman.
2. Click **Import** and select `postman/TeamBoard_API.postman_collection.json`.
3. The collection uses dynamic variables (`base_url`, `client_token`, `admin_token`, `api_key`).
4. Click **Run collection** to execute all scenarios sequentially. All test assertions will pass automatically.

```bash
docker exec -it teamboard_postgres psql -U teamboard_user -d teamboard_db
```

Query tables:
```sql
\dt
-- Displays:
-- api_company
-- api_kbentry
-- api_querylog
```

Inspect company and API key generation:
```sql
SELECT id, company_name, role, api_key, created_at FROM api_company;
```

```sql
SELECT id, company_id, search_term, results_count, queried_at FROM api_querylog;
```
